# Decisions

This document holds the decisions that govern FuguOracle. A plan must not go
against a decision. To change a decision, propose the change and get human
approval first.

| ID   | Decision                                                                                                                                                                                                                                                                                                                                                                                      | Rationale                                                                                                                                                                                                                                                                                      |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D-01 | FuguOracle is a generic blind PIN oracle and a virtual secure element. The design, the interfaces, and the documentation must not bind the service to one client product. Blockstream Jade is the reference client, not the only client.                                                                                                                                                      | The oracle protects any low-entropy PIN scheme that speaks the protocol.                                                                                                                                                                                                                       |
| D-02 | The service implements protocol v2 only. The service must not implement protocol v1, sessions, or a handshake endpoint.                                                                                                                                                                                                                                                                       | Current clients speak v2. v2 is stateless, so the service needs no session table and no lifetime configuration.                                                                                                                                                                                |
| D-03 | The project must not reimplement cryptographic primitives. All curve operations come from `libsecp256k1`. All symmetric operations come from LibreSSL `libcrypto`.                                                                                                                                                                                                                            | These libraries give constant-time, tested primitives with the exact semantics that the wire protocol assumes.                                                                                                                                                                                 |
| D-04 | The service runs as a statically linked CGI program behind `httpd(8)` and `slowcgi(8)`, with one process per request.                                                                                                                                                                                                                                                                         | Each request gets a fresh address space. Secrets live for milliseconds. The workload is a few requests per day.                                                                                                                                                                                |
| D-05 | PIN records live as flat files in one directory. The service must not use a database.                                                                                                                                                                                                                                                                                                         | The workload is small. Flat files keep the code and the audit surface small.                                                                                                                                                                                                                   |
| D-06 | Configuration paths are compile-time constants. The service must not read a configuration file or environment configuration.                                                                                                                                                                                                                                                                  | The man page documents the paths. OpenBSD practice favors fixed paths for chrooted CGI programs.                                                                                                                                                                                               |
| D-07 | The implementation language is C, in KNF per `style(9)`. The target platform is OpenBSD -stable.                                                                                                                                                                                                                                                                                              | The service integrates with the OpenBSD base system and its ports tree.                                                                                                                                                                                                                        |
| D-08 | New code carries the ISC license. The wire behavior stays compatible with the MIT-licensed upstream `blind_pin_server`.                                                                                                                                                                                                                                                                       | ISC is the OpenBSD house license. Wire compatibility preserves the installed client base.                                                                                                                                                                                                      |
| D-09 | The record format is version `0x01` only. The service must not implement a record migration.                                                                                                                                                                                                                                                                                                  | Fresh deployments write and read one format. Migrations add code with no user.                                                                                                                                                                                                                 |
| D-10 | On `get_pin`, after the request envelope decrypts and the payload fields extract, every failure except an I/O failure must return HTTP 200 with a junk key. An I/O failure returns status `500` (see OPS-GET-7). A caller must not learn the cause of any other `get_pin` failure. On `set_pin`, every failure must return an HTTP error status.                                              | The `get_pin` failure rule carries the design: only the client can detect a bad key, by its own decrypt failure. A junk key on `set_pin` is undetectable by the client, and it desynchronizes the client from the oracle. An attempt that the service cannot count must not receive an answer. |
| D-11 | One global advisory lock serializes the load, decide, and store steps. The service must not use per-record locks.                                                                                                                                                                                                                                                                             | Coarse locking is correct, and the workload makes contention irrelevant.                                                                                                                                                                                                                       |
| D-12 | Acceptance is behavioral equality with the upstream server for well-formed requests: the same reject, junk, or real decision, and byte-identical `200` response bodies for identical input and identical stored state, given one fixed random source with a pinned draw order in both servers. HTTP error surfaces, and the deviations that the table in overview.md lists, are out of scope. | Byte equality on the success surface is the strongest testable compatibility claim. The error surface deviates by design, and the comparison needs a patched random source in the upstream server.                                                                                             |
